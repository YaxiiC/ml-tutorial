# 零基础机器学习 / 深度学习项目：分步 Prompt 手册

用 AI 助手（ChatGPT、Claude、Gemini 等）一步一步完成一个完整的机器学习项目：从定义问题、相关性分析，到模型比较、特征重要性分析和项目报告。

设计思路：**一个 prompt 只做一步，每一步都要求 AI 解释原因、给出可运行的代码，并在关键处停下来让你确认。** 整套流程严格按照机器学习 best practice 的顺序：**先把测试集留出来，再做任何分析。**

> 想先看一个完整的例子？本仓库的 [`ML-tutorial.ipynb`](../ML-tutorial.ipynb) 就是按照这套流程完成的。

## 使用说明

1. **一次只发一个 prompt。** 把 AI 给的代码复制到 Colab 里运行，再把**运行结果（包括报错）贴回给 AI**，然后才进入下一步。
2. 【方括号】里的内容换成你自己项目的信息。
3. 每个 prompt 后面都有 **✅ 检查点**：自己能回答这些问题，再往下走。答不上来，就让 AI 再解释一遍。
4. **永远不要跳过 P3（切分数据）。** 这是整个项目最容易出错、也最致命的地方。
5. AI 写的代码也会出错。看不懂的地方，直接问它"这一行在做什么？为什么要这么写？"

## 整体流程

```
P0 总设定 → P1 明确问题 → P2 数据体检 → P3 切分（锁住测试集）→ P4 探索性分析与相关性
→ P5 预处理 Pipeline → P6 基线模型 → P7 多模型比较 + 交叉验证 + 调参
→ P8 最终测试（只做一次）→ P9 错误分析 → P10 特征重要性与可解释性 → P11 复现与报告
（图像数据 → 走深度学习分支 DL1–DL3）
最后：P12 全面自检
```

## P0 · 总设定（每次开新对话时先发这一条）

```text
你是一位耐心的机器学习导师，正在一步一步带我完成一个机器学习项目。

【我的背景】
- 我是【机械工程 / 材料工程 / ……】方向的研究生，Python 基础【很少 / 会一点】，没有系统学过机器学习。
- 我在 Google Colab 里运行代码。

【我的项目】
- 研究问题：【用一两句话描述，例如：根据焊接工艺参数预测焊缝的抗拉强度】
- 数据：【文件名、大概多少行多少列、每一行代表什么，例如：weld.csv，约 800 行，每行是一次焊接实验】
- 想预测的目标：【列名，例如 tensile_strength】

【请你始终遵守以下规则】
1. 一次只做我要求的这一步，不要提前把后面的步骤都写完。
2. 代码必须能在 Colab 里直接运行；每一行关键代码都加中文注释，解释"在做什么"和"为什么这么做"。
3. 专业术语第一次出现时，用一句通俗的话解释，并保留英文原词。
4. 遵守机器学习 best practice：
   - 固定随机种子（random_state=42），保证结果可复现；
   - 测试集在最终评估前绝对不能用于任何决策（包括看分布、选特征、调参）；
   - 所有预处理（填补缺失值、标准化、编码）都放进 sklearn Pipeline，只在训练数据上 fit；
   - 任何模型都要和一个简单的基线模型比较；
   - 报告结果时给出波动范围（例如交叉验证的 mean ± std），而不是只给一个数字。
5. 如果信息不够、需要做假设，先停下来问我，不要自己猜。
6. 每一步结束时，用 3–5 句话总结"这一步得到了什么结论"，并告诉我需要把哪些输出贴回给你。

如果明白了，请用你自己的话复述一遍我的项目和这些规则，然后等我发下一步。
```

✅ **检查点**：AI 复述的项目理解是否正确？不对就马上纠正。

## P1 · 明确问题：先想清楚再写代码

```text
第 1 步：在写任何代码之前，请帮我把问题定义清楚。

请回答并和我讨论：
1. 这是分类问题还是回归问题？为什么？
2. 每一行数据代表什么"样本"？有没有可能同一个对象（同一个零件、同一位病人、同一批材料）出现在多行里？
   如果有，后面切分数据时需要按"组"切分，请提醒我。
3. 应该用什么评估指标？请结合实际后果解释：
   - 分类：漏检（假阴性）和误报（假阳性）哪个代价更大？因此应该重点看 recall、precision、F1、ROC-AUC 还是 PR-AUC？
   - 回归：MAE 和 RMSE 分别适合什么情况？R² 怎么理解？
4. 什么叫"基线模型"（baseline）？在我的问题里，最简单的基线是什么？
5. 模型达到什么水平才算"有用"？请帮我写一个具体、可衡量的成功标准。
6. 有哪些列在实际使用时是"预测的时候还拿不到"的？（例如事后才测得的结果）这些列不能当特征，否则就是数据泄漏。

最后请把结论整理成一张"项目定义表"：任务类型、样本单位、目标列、主要指标、次要指标、基线、成功标准、需要排除的列。
```

✅ **检查点**：我能说清楚"我的模型错了的话，哪种错误最糟糕"吗？

## P2 · 数据体检

```text
第 2 步：加载数据并做一次全面"体检"。这一步只看数据质量，不做建模。

请写代码完成：
1. 读取数据，打印前 5 行、形状（行数、列数）、每一列的数据类型。
2. 缺失值：每一列缺失多少、占比多少，用柱状图展示。
3. 重复行：有没有完全重复的行？
4. 目标列：
   - 分类：每一类有多少个、占比多少？是否类别不平衡？
   - 回归：均值、标准差、最小值、最大值，画直方图，看是否严重偏斜或有异常值。
5. 数值列：用 describe() 看范围，指出明显不合理的值（例如负的温度、超出物理范围的值）。
6. 类别列：每一列有多少个不同取值？有没有拼写不一致（例如 "Steel" 和 "steel"）？
7. 有没有 ID 类的列（编号、日期、文件名）？它们一般不该直接当特征，请说明原因。

注意：这一步只"发现问题"，先不要删除或修改任何数据。
最后列一个"数据问题清单"，每个问题给出建议的处理方式，并说明这个处理应该放在 Pipeline 里还是可以在切分之前做。
```

> 💡 **说明**：只有**不依赖数据统计量**的清理（删完全重复的行、统一拼写、删明显录错的行）可以在切分之前做；**依赖统计量**的处理（用均值填补缺失、标准化）必须放进 Pipeline。

✅ **检查点**：我的数据有哪几个问题？分别打算怎么处理？

## P3 · 切分数据，锁住测试集

```text
第 3 步：切分训练集和测试集。这一步非常关键，请详细解释。

要求：
1. 先只做"不依赖统计量"的清理（例如删除完全重复的行、统一拼写），然后再切分。
2. 留出 20% 作为测试集，random_state=42。
   - 分类问题：使用 stratify，保证两边类别比例一致；
   - 如果第 1 步发现同一个对象有多行：使用 GroupShuffleSplit 按组切分，保证同一个对象不会同时出现在训练集和测试集；
   - 如果数据有时间顺序，且未来要用来预测"以后"的数据：按时间切分，而不是随机切分。
3. 打印训练集和测试集的大小，以及目标分布，确认切分合理。
4. 用通俗的语言解释：
   - 为什么测试集要在一开始就留出来，而不是分析完再切？
   - 什么是数据泄漏（data leakage）？举 2 个在我这个项目里可能发生的具体例子。
5. 从这一步开始，后面所有的分析、可视化、选特征、调参，都只能用训练集。
   请在代码里把测试集变量命名为 X_test_LOCKED, y_test_LOCKED，提醒我在第 8 步之前不要碰它们。
```

✅ **检查点**：如果我在全部数据上算了均值来填补缺失值，再切分，为什么是错的？

## P4 · 探索性分析与相关性分析（只用训练集）

```text
第 4 步：在训练集上做探索性数据分析（EDA），重点是相关性分析。

请写代码完成：
1. 每个数值特征的分布：直方图或箱线图，指出偏斜和异常值。
2. 每个特征和目标的关系：
   - 回归：画散点图（特征 vs 目标）；同时计算 Pearson 相关系数（线性关系）和 Spearman 相关系数（单调关系），
     两者差别很大时，说明可能存在非线性关系，请指出来。
   - 分类：按类别分组画箱线图或小提琴图，看每个特征在两类之间有没有明显差别；
     计算每个特征和目标的相关系数（目标用 0/1 表示，并说明正负号的含义）。
   - 把所有特征和目标的相关系数排好序，画成横向柱状图。
3. 特征之间的相关性：
   - 画相关系数热力图（特征多于 15 个时不要在格子里写数字）；
   - 找出相关系数绝对值大于 0.8 的特征对，解释为什么这叫"多重共线性"，以及它会影响什么（线性模型系数不稳定、特征重要性被分摊）。
4. 类别特征：每个取值下目标的平均值或比例。
5. 请提醒我：
   - 相关 ≠ 因果；
   - 相关系数只能发现线性或单调关系，相关系数低不代表这个特征没用；
   - 这一步的目的是"理解数据、建立预期"，不是用来删特征的（除非有明确的领域理由）。

图里的文字请用英文，避免 Colab 中文字体显示成方框；解释写在注释和文字里。
最后用 5 句话总结：哪些特征可能最重要？有没有高度相关的特征？你预期模型大概能做到什么水平？
```

✅ **检查点**：把"和目标最相关的 3 个特征"记下来，**P10 要和模型的特征重要性对比**。

## P5 · 预处理：搭建 Pipeline

```text
第 5 步：搭建预处理 Pipeline。

请用 sklearn 的 ColumnTransformer + Pipeline 完成：
1. 数值列：缺失值用中位数填补（SimpleImputer(strategy="median")），然后标准化（StandardScaler）。
2. 类别列：缺失值用最常见值填补，然后 OneHotEncoder(handle_unknown="ignore")。
3. 解释每一步为什么需要，以及为什么必须放进 Pipeline：
   - Pipeline 在交叉验证的每一折里，只用这一折的训练部分 fit，验证部分不会"偷看"；
   - 部署时，新数据会自动经过完全相同的处理。
4. 说明哪些模型需要标准化（线性模型、SVM、神经网络、KNN），哪些不需要（决策树、随机森林、梯度提升树）。
5. 先不要训练模型，只要把 Pipeline 定义好，并在训练集上 fit_transform 一次，打印处理后的形状，确认没有报错。
```

✅ **检查点**：为什么 `scaler.fit(X_test)` 是错的？

## P6 · 基线模型

```text
第 6 步：建立基线模型。

请完成：
1. 一个"什么都不学"的基线：
   - 回归：DummyRegressor(strategy="mean")，永远猜训练集的平均值；
   - 分类：DummyClassifier(strategy="most_frequent")，永远猜最多的那一类。
2. 一个简单的可解释模型：
   - 回归：Pipeline(预处理 + Ridge)；
   - 分类：Pipeline(预处理 + LogisticRegression(max_iter=1000))。
3. 用 5 折交叉验证在训练集上评估这两个模型（分类用 StratifiedKFold，有分组就用 GroupKFold），
   报告第 1 步定好的指标，格式为 mean ± std。
4. 解释：为什么"永远猜多数类"的模型准确率可能很高？这对我们解读后面的结果有什么启示？
```

✅ **检查点**：基线的分数是多少？后面任何模型都必须**明显**超过它。

## P7 · 多模型比较、交叉验证与调参

```text
第 7 步：比较几种模型，并做超参数调优。全部只在训练集上用交叉验证完成。

请完成：
1. 至少比较这几种模型（都放在和第 5 步相同的预处理 Pipeline 里）：
   - 线性模型（Ridge / LogisticRegression）
   - 随机森林（RandomForest）
   - 梯度提升树（HistGradientBoosting）
2. 每个模型先用默认参数做 5 折交叉验证，报告 mean ± std。
3. 对表现最好的 1–2 个模型，用 RandomizedSearchCV 或 GridSearchCV 调参：
   - 解释每个超参数的含义（例如 n_estimators、max_depth、learning_rate、正则化强度 alpha 或 C）；
   - 搜索范围不要太大，控制运行时间在几分钟内；
   - 说明为什么调参也必须在交叉验证里做，而不能看测试集。
4. 可视化：
   - 柱状图 + 误差线：每个模型的交叉验证分数，并画出每一折的散点；
   - 如果两个模型的差距小于它们的标准差，请明确告诉我"差别不显著"。
5. 检查过拟合：比较训练分数和交叉验证分数，差距很大说明什么？
6. 选出最终模型，并说明理由。不只看分数，还要考虑：稳定性（std）、可解释性、训练速度。
```

✅ **检查点**：最终模型是哪个？它比基线好多少？比第二名好得"显著"吗？

## P8 · 最终测试集评估（只做一次）

```text
第 8 步：用测试集做最终评估。这一步只做一次，做完之后不能再回去改模型。

请完成：
1. 用第 7 步选定的最终模型（包括调好的参数），在完整训练集上重新训练一次。
2. 解锁 X_test_LOCKED, y_test_LOCKED，在测试集上评估：
   - 分类：classification_report、混淆矩阵（ConfusionMatrixDisplay）、ROC 曲线和 AUC；
     如果类别不平衡，加上 Precision-Recall 曲线和 PR-AUC。
   - 回归：MAE、RMSE、R²；"真实值 vs 预测值"散点图（加对角线）；残差图（残差 vs 预测值）。
3. 和交叉验证的结果比较：测试集分数是否在交叉验证的 mean ± std 范围内？
   如果差很多，可能是什么原因？
4. 分类问题额外做：
   - 解释"阈值"（默认 0.5）的含义；
   - 画出不同阈值下 precision 和 recall 的变化；
   - 根据第 1 步确定的"哪种错误更严重"，讨论是否应该调整阈值。
     注意：理想做法是在训练集的交叉验证里选阈值，而不是在测试集上挑一个最好看的。
5. 用通俗的语言写一段话："如果把这个模型用在实际中，它大概能做到什么，做不到什么。"
```

✅ **检查点**：测试集结果和交叉验证结果一致吗？我有没有因为测试结果不好又回去改模型？（改了就不能再叫"测试集结果"）

## P9 · 错误分析

```text
第 9 步：分析模型在哪里出错。

请完成：
1. 找出测试集里预测错误最严重的 10 个样本（分类：预测概率错得最离谱的；回归：残差绝对值最大的）。
2. 把它们和预测正确的样本对比：在哪些特征上有明显不同？
3. 按某个重要特征或类别分组，看模型在哪些子群体上表现明显变差（例如某种材料、某个温度区间）。
4. 讨论可能的原因：数据太少？测量噪声？缺少关键特征？标签本身有错误？
5. 给出 2–3 条具体的改进建议，并说明哪些是"多收集数据"能解决的，哪些是"换模型"能解决的。
```

✅ **检查点**：模型在哪类样本上最不可靠？使用时需要提醒什么？

## P10 · 特征重要性与可解释性

```text
第 10 步：分析哪些特征对模型的预测最重要。请用多种方法，并解释每种方法的优缺点。

请完成：
1. 模型自带的重要性：
   - 线性模型：在标准化后的数据上看系数（coef_），解释正负号和大小的含义；
   - 树模型：feature_importances_（基于不纯度）。请说明它的缺点：
     偏向取值多的特征、在训练集上计算、高度相关的特征会互相"分摊"重要性。
2. 置换重要性（Permutation Importance）—— 主要方法：
   - 用 sklearn.inspection.permutation_importance，在测试集上计算，n_repeats=30，random_state=42；
   - 用通俗的话解释原理："把某一列打乱，模型变差了多少，就说明它有多重要"；
   - 画出带误差线的横向柱状图（mean ± std）；
   - 提醒：如果两个特征高度相关，打乱其中一个，另一个还能"顶替"，两者的重要性都会被低估。
     请根据第 4 步发现的高相关特征对，把它们作为一组一起打乱，再算一次"组重要性"。
3. SHAP 值（选做，需要 pip install shap）：
   - 画 summary plot（beeswarm），解释每个点的含义：颜色 = 特征值高低，横坐标 = 对预测的影响方向和大小；
   - 对最重要的 2 个特征画 dependence plot，看影响是线性的还是非线性的。
4. 部分依赖图（Partial Dependence Plot）：对最重要的 2–3 个特征，用 PartialDependenceDisplay 画出
   "其他条件不变时，这个特征变化，预测值怎么变化"。
5. 和第 4 步对比：
   - 第 4 步里和目标最相关的特征，现在是否也最重要？
   - 如果不一致，可能的原因是什么？（非线性关系、特征之间的交互作用、多重共线性）
6. 用领域知识检验：最重要的特征在【我的专业领域】里说得通吗？
   如果某个特征重要得"不合理"（例如样本编号、测量日期），很可能是数据泄漏，请提醒我回到第 1 步检查。
7. 最后请特别强调：
   - 特征重要性说明的是"模型依赖什么"，不是"现实中什么导致了结果"（重要性 ≠ 因果关系）；
   - 重要性是针对"这个模型 + 这份数据"的，换模型或换数据可能会变。

最后列一张总结表：特征名 | 相关系数（第 4 步）| 置换重要性 | SHAP 平均绝对值 | 物理上是否合理 | 备注。
```

✅ **检查点**：我能用一句话向导师解释"模型最依赖哪 3 个特征，以及为什么这在物理上说得通"吗？

# 深度学习分支（图像数据）

> 如果数据是**表格**（一行数字），优先用上面的 P1–P12：在小样本表格数据上，梯度提升树通常比神经网络更好，也更好解释。
> 如果数据是**图片**（缺陷照片、显微图像、X 光），用下面三步替换 P4–P10。P1–P3 和 P11–P12 照常使用。

## DL1 · 图像数据准备与切分

```text
深度学习第 1 步：准备图像数据。

【我的数据】：【例如：约 1300 张零件表面灰度照片，按文件夹分为 good / defect 两类】

请完成：
1. 统计每一类有多少张图片，检查类别是否平衡；随机展示每一类各 4 张图片。
2. 检查图片尺寸、通道数（灰度 / 彩色）是否一致；统计尺寸分布。
3. 切分为训练集 / 验证集 / 测试集 = 70% / 15% / 15%（stratify，random_state=42）：
   - 解释为什么深度学习需要单独的验证集（用来选择 epoch、调学习率、提前停止），而测试集只在最后用一次；
   - 如果同一个零件拍了多张照片，必须按零件切分，否则模型会"认出零件"而不是"认出缺陷"。
4. 预处理：统一缩放到【例如 128×128】，像素归一化。解释为什么归一化的统计量只能从训练集计算。
5. 数据增强（只用在训练集上）：随机翻转、小角度旋转、亮度变化等。
   请说明每种增强在我的场景里是否"物理上合理"（增强后的图片标签必须不变）。
6. 用 PyTorch 的 Dataset 和 DataLoader 组织数据，并取出一个 batch，打印形状、显示图片，确认没有问题。
```

## DL2 · 搭建与训练模型

```text
深度学习第 2 步：搭建并训练模型。

请完成：
1. 先建立两个对照：
   - 基线：永远预测多数类的准确率；
   - 一个小的 CNN（3–4 个卷积块：Conv2d → BatchNorm → ReLU → MaxPool），解释每一层的作用；
     特别说明"卷积核"和传统图像滤波（例如 Sobel 边缘检测）的关系。
2. 再做一个迁移学习版本：使用 ImageNet 预训练的 ResNet18，替换最后一层，
   解释什么是迁移学习，以及为什么在小数据集上通常效果更好。
3. 训练循环要求：
   - 每个 epoch 结束时，同时记录训练集和验证集的 loss 和指标；
   - 使用学习率调度（例如 CosineAnnealingLR），并解释学习率的作用（可以用"下山时每一步迈多远"来比喻）；
   - 保存验证集表现最好的那个 epoch 的模型权重（best checkpoint），而不是最后一个 epoch 的；
   - 早停（early stopping）：验证集连续若干个 epoch 没有改进就停止；
   - 类别不平衡时，考虑在损失函数里加类别权重，并解释原因。
4. 画训练曲线：训练 loss vs 验证 loss、训练指标 vs 验证指标。
   请教我怎么从曲线判断"欠拟合""刚好""过拟合"。
5. 固定随机种子，并说明在 GPU 上结果可能仍有微小差异的原因。
6. 用中文逐行解释训练循环里的四步：前向传播、zero_grad、backward、step。
```

## DL3 · 评估与可解释性

```text
深度学习第 3 步：在测试集上评估，并解释模型在"看"哪里。

请完成：
1. 加载验证集上最好的模型，在测试集上只评估一次：
   classification_report、混淆矩阵、ROC 曲线 / PR 曲线，并和基线比较。
2. 展示预测错误的图片（假阴性和假阳性分开），讨论它们有什么共同点。
3. 可解释性（对应表格数据的"特征重要性"）：
   - 用 Grad-CAM 画热力图，显示模型做判断时主要关注图片的哪些区域；
   - 对正确和错误的样本各选几张，检查模型是否真的在看"缺陷位置"，
     还是在看背景、边框、文字标记等无关区域（"捷径学习" shortcut learning）；
   - 如果模型关注的是无关区域，说明数据可能有偏差，需要回到 DL1 检查。
4. 对比小 CNN 和 ResNet18：准确率、训练时间、参数量，哪个更适合我的场景？
5. 总结局限性：数据量、拍摄条件（光照、相机、角度）变化时模型是否还可靠。
```

## 附：常见错误清单

| 错误 | 为什么错 | 正确做法 |
|---|---|---|
| 先标准化 / 填补缺失值，再切分 | 测试集的信息泄漏进了训练 | 先切分，预处理放进 Pipeline |
| 在全部数据上看相关性、选特征 | 选特征也是一种"训练"，偷看了测试集 | EDA 和选特征只用训练集 |
| 只看准确率 | 类别不平衡时，"全猜多数类"准确率也很高 | 看 recall / precision / AUC，和基线比 |
| 根据测试集结果反复改模型 | 测试集变成了"调参集"，结果虚高 | 用交叉验证或验证集做决策，测试集只用一次 |
| 只报告一个数字 | 换一次随机切分，结果可能差很多 | 报告 mean ± std |
| 把特征重要性说成因果 | 重要性只说明模型依赖什么 | 结合领域知识，谨慎表述 |
| 同一零件 / 病人的数据同时在训练集和测试集 | 模型"认出了对象"，而不是学到了规律 | 按组切分（GroupKFold） |
| 用最后一个 epoch 的深度学习模型 | 可能已经过拟合 | 保存验证集最好的 checkpoint |
